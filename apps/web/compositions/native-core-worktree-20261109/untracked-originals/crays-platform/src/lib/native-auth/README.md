# Native Core admission: initial registered Bootstrap path

This isolated worktree contains the first native Bearer admission branch in the existing Core DAL and GraphQL handler. It uses the existing provider-subject repository, Core mapper and permission evaluator. The same Auth0/Core authority is returned; native transport provenance is held privately per Request. Browser SDK sessions are neither constructed nor forged.

The route admits only POST /api/graphql with the already registered PlatformBootstrap APQ hash. Arbitrary query text, other operations, nonempty variables, URL query parameters, cookies, batching, a different Request and a changed Authorization header are refused. This restriction is an initial integration stage, not the final app API: further reads/commands require their own registered operations, OAuth scopes and canonical domain authorization. Opening this branch does not expose generic native access to existing REST or command routes.

Configuration is disabled unless CRAYS_NATIVE_AUTH_ENABLED=true. It additionally requires explicit CRAYS_NATIVE_AUTH_ISSUER, CRAYS_NATIVE_AUTH_AUDIENCE, CRAYS_NATIVE_AUTH_CLIENT_IDS, CRAYS_NATIVE_AUTH_IDENTITY_SCOPE and CRAYS_NATIVE_AUTH_BOOTSTRAP_SCOPE. No example scope in tests is a registered real scope. No Auth0 tenant, native application, API, billing or AI entitlement has been changed. The current Swift login requests provider scopes only and cannot use this API until its real audience/scopes are qualified.

The account must be active, have no unresolved Core actions, and have one unambiguous active organization assignment for the mapped role and the same verified Nostr key. The current personal/global context without an organization and multiple-organization context remain explicit integration gaps requiring a canonical selection contract. Do not create a Venue/Gym membership or use a review-tenant fallback to make those cases pass. This admission is not full onboarding, device revocation, signer recovery or any product acceptance.

Run node --test scripts/ios-native-auth-qualification/auth.test.mjs from crays-platform for 30 tests. Actual jose JWT verification and the actual new native branch, DAL, mapper and Core permission code execute. The database and browser Auth0 ports are controlled fixtures. These are not actual database, HTTP/Yoga, hosted Auth0 or physical-device tests. The full repository TypeScript check currently reports the same 14 errors before and after this change; those errors remain blockers for a complete Core build. No deployment or live service mutation was performed.

Only approved jose6.2.3 is newly named directly in package metadata; it was already the exact transitive Core-lock version. Copied native-auth0-verifier.mjs and native-core-identity-boundary.mjs retain the previously qualified candidate bytes. The adjacent native-core-auth.ts supplies actual server-owned ports and the bounded route admission. Its runtime remains disabled until explicitly configured and qualified.
