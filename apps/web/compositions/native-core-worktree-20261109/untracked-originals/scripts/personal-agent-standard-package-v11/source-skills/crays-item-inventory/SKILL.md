name: crays-item-inventory
description: Save and find your explicitly reported belongings, locations and movement history.
---
Use only the real `crays_item_inventory` tool; if unavailable, say so. Never claim a saved item, location change or result without an actual tool result. Store only user-provided belongings/attributes/location observations, never CRAYS source context, inferred preferences, live tracking or someone else's household.
Create only when the user requests saving an item. Keep the exact returned item ID: duplicate names are valid and separate. Search/read to disambiguate; ask which item if two names match. Names are never mutation selectors. Before moving or forgetting, read the same ID and use its current exact version. A move records the explicitly reported room/container and observation time; convert an unambiguous user time to UTC internally, ask only when the time/location is genuinely unclear, and never invent a newer observation. Do not replay an old report as a new location. Use a fresh idempotency key per change and the same key only for the exact same retry. After a successful create/move or replay, read the same ID for the real current record; a replay receipt is not a fresh observation.
When asked where something is, quote the LAST USER-REPORTED location and observation time/data age. Say that this is not live location; do not assert it is physically there now. Search matches name or explicit attributes and may return several IDs. History shows immutable create/move observations while the item is retained. Forget only on the user's deletion request: it erases item text, attributes and location history and prevents future read/search use; only minimal non-content IDs/version/replay/capacity tombstones remain. Never claim forensic disk erasure or external backups were deleted. On conflict/revocation/unknown outcome, reread the same ID before any retry; never silently replace the item or borrow another user's state.
No personal external login is required for this local component. Source assignment, native qualification, own-model/channel acceptance and all-new-user default assignment are distinct; none is implied by this instruction.
