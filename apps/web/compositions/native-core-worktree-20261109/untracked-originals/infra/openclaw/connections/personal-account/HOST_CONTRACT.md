# Chuck — first-party own-account OAuth source candidate

This directory contains adopted, tested server-side connection foundations, not a connected account. The component, actual private Postgres, Auth0 SDK and synthetic OS-credential proofs below record their exact scopes. No real provider login, operational app-secret delivery, deployed connection route, applied Core migration or Chuck account connection is claimed. All future CRAYS people use the same optional connection feature across Verticals, each with their own credentials/data/memory/scopes. Core remains the sole person/account authority. No Twenty installation prerequisite. All 555 tasks and wider LinkedIn/communication obligations remain open beyond this bounded branch.

## Source composition

`core-person.mjs` repeats the actual existing Core Auth0→account→canonical_people relation in one read-only repeatable-read query. Account status, person lifecycle and actual `person_version` enter the currentness fingerprint. SQL IDs are bounded strings, never filesystem paths; any future per-person physical namespace must be a separate server-derived digest. No new role, model login or baseline readiness is required for linking mail. `getAuth0Session(request)` must call the existing `auth0.getSession(request)` in the real authenticated BFF. `getClient` is `getCorePgPool().connect()`. `getVerifiedSessionBinding` must derive a stable, opaque server-authenticated session identity from that actual session; it may not read model arguments, portal bridge cookies, review personas or unverified headers. The adopted `crays-platform/src/lib/personal-account-auth0-core.ts` now implements this host binding through the actual SDK and exact `NextRequest`. Its semantic compile and six encrypted synthetic SDK-session cases passed; it is not yet consumed by a deployed connection route. Results are frozen and registered in a per-resolver-instance WeakSet; `assertResolvedPerson` rejects object copies and outputs from another resolver instance.

`oauth-connection-service.mjs` obtains all identity through that host resolver. Browser inputs contain provider/actions, opaque attempt/connection handle, callback state/code/error, and expected connection version only. begin creates a ten-minute one-use attempt bound to current account/person/session, exact configured app/client/HTTPS redirect/fingerprint and requested action set. It generates random state/nonce and S256 PKCE for Google/Microsoft. LinkedIn here follows its confidential-server documented code flow and OIDC profile-only scope. No caller URL, HTML, secret or person selection exists.

Callback atomically claims state before any exchange, rejects denial/replay/expiry/mismatch, exchanges only at fixed official endpoints and checks the real JOSE verifier plus userinfo subject equality. Requested resource scopes must appear in actual token scope readback. No token-scope fallback from requested permissions. Returned connection metadata is redacted, vault refs remain internal. Existing token expiry is checked. The adopted refresh repository durably journals refresh attempts and handles unknown outcomes; a provider refresh executor and reconnect workflow are still pending and are not implied by that repository. Read/write/send are distinct local grants even where provider scopes overlap. Draft permission never locally grants send; token may technically cover more than the chosen local action. `mail.modify` represents an explicit modification grant, not permission granted by a read connection. Gmail immediate permanent deletion is outside this initial catalog and remains wider implementation work, not falsely completed.

`oidc-verifier.mjs` actually invokes existing original JOSE jwtVerify/createLocalJWKSet with RS256 only, official fixed public-key endpoints, issuer/audience/signature/nonce/iat/expiry/subject checks and Microsoft UUID tenant-specific issuer validation. Decoding Microsoft's untrusted tid merely constructs an expected issuer under a fixed host; it is not identity validation or authority. It never determines a fetch URL. Foreign embedded key URLs and mismatched azp are rejected. Keys are bounded/cached for five minutes; key rotation cache miss currently fails closed until refresh/retry rather than an unbounded fetch loop. The installed original `jose` 6.2.12 (MIT) is a source/test dependency, not claimed newly runtime-admitted. Exact original files will be read-only pinned in the finite component packet; no package download or SDK mutation.

`fixed-provider-transport.mjs` implements fixed endpoint/method fetch with no redirect, credentials/cookies or cache, 15-second service abort and a streamed 64KiB body cap. Public-key fetch has a fixed endpoint set, 10-second abort and 256KiB cap. No automatic retries or raw provider errors/log output.

## Durable host store contract — required before any connection can work

All methods are host-owned, not model-callable. Missing methods fail constructor checks. The adopted `person-pg-context.mjs`, `attempt-repository.mjs`, `vault.mjs`, `refresh-repository.mjs`, `envelope.mjs` and `server-oauth-persistence.mjs` provide real private-Postgres and encrypted persistence implementations. Six cryptographic and thirteen real private-Postgres cases passed, including concurrent claims and unknown outcomes. `personal-oauth-schema.proposed.sql` remains a proposed schema; operational Core migration/RLS/grants and route wiring are pending. In-memory component fixtures alone do not prove deployment.

- `createAttempt(attempt)`: durable insert-if-absent with unique state digest, owner/person/session/provider/app/redirect/scopes/nonce/PKCE+expiry. Treat nonce/verifier and attempt state as private encrypted-at-rest data through the existing host vault. Never store raw state. Bound concurrent attempts with expired-attempt cleanup and request rate limits; do not invent lifetime login quotas or delete required audit history.
- `claimAttempt(binding)`: one atomic committed compare-and-transition PENDING→CLAIMED where EVERY supplied binding matches and expiry is future. Foreign/mismatched attempts are not consumed. Return the complete original attempt only for the winner. A second call cannot exchange the code. No caller-supplied approval boolean substitutes for this transaction.
- `commitConnection(row)`: one atomic durable transaction consumes that claimed attempt, rechecks unchanged Core account/person/version/session authority, exact request binding, expiry and selected action/scope set; inserts the person-owned connection and attempt→outcome relation. Account identity is app/issuer/provider-subject bound, not email/profile URL. Reconnect must use its own attempt, replace/revoke prior current handle for the same person/provider/app/subject with CAS and preserve history. Do not activate another account's existing token. Row state CONNECTED is allowed ONLY after actual callback validation, vault sealing and durable readback; source preparation never sets it operationally.
- `getAttemptOutcome({attemptId,accountId,canonicalPersonId,sessionBinding})`: exact owned readback of that attempt's durable completion/current revocation state; never resurrect a disconnected connection from an old completion snapshot. Used after COMMIT_OUTCOME_UNKNOWN. A claimed but uncommitted attempt requires reconnect/reconciliation, never blind code replay.
- `getConnection({handle,accountId,canonicalPersonId})`: current full internal row only for exact ownership, with current version/state/actions/granted scopes/expiry/credentialRef/app fingerprint. `revokeConnection` performs owned expected-version CAS to REVOKED before returning internal credentialRef. It must invalidate pending attempts/commits to the affected connection generation as appropriate. Foreign reads/revokes return absence. Version/revocation is checked again by the host operation immediately before external IO; no background credential fallback.

The service rechecks actual Core authority around asynchronous callback steps. No application check can replace the final same-Core-transaction authority check required at commit. `personVersion`, statuses and subject/session fingerprint must be included in persisted attempt/commit authority. Routes must expose safe public error enums only, never arbitrary database/vault/provider error strings. Existing service code returns safe callback errors; framework integration remains required for other host failure responses.

## Vault and unknown outcome contract

- `withAppSecret(secretRef,callback)` resolves only an allowlisted configured app reference internally and never returns the secret to route/model/logs.
- `seal({accountId,canonicalPersonId,provider,handle,credentials,expiresAt})` durably encrypts for that exact owner/handle and returns an opaque ref only. No pathname authority. Lifecycle cleanup/audit is host-owned.
- `destroy(ref)` disables/removes credential access. Local disconnect revokes the store first; failed destruction returns cleanupPending, while old handle remains denied. Remote provider revocation is separate and explicitly false here.

Before commit starts, failed callback attempts destroy a newly sealed credential. Once commit starts, an uncertain response preserves it for exact durable reconciliation; it must not delete a credential that may already back a committed row, nor report NOT_SAVED when commit may have succeeded. Reconciliation uses the original owned attempt handle, never repeats code exchange. Uncommitted orphan refs need bounded host cleanup after durable outcome reconciliation. No infinite retry or unbounded stale cleanup engine is introduced.

`withConnection` is server-only: its `execute` callback is fixed production adapter code, never request/model code. It receives only the internal vault reference and currentness callback. Actual mailbox/calendar adapters must resolve credential inside the vault, enforce the exact action, invoke currentness immediately before provider IO, return bounded redacted data and preserve provider write receipts/unknown reconciliation. Connection authorization does not itself implement mail sends, reads or calendar mutation.
